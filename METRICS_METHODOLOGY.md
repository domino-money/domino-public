# Pool activity and metrics methodology

9 September 2026. Local API 0.7.0 adds event-time capital history, persisted external price observations, a conditional USD/fee-APR calculation engine and official PositionManager NFT-owner reads at a pinned block. Activity, fees, positions and capital each retain independent methodology version 1. Production dollar metrics remain unavailable: no price source has yet passed the required Robinhood identity, independence and timestamp-semantics qualification. This does not change Domino's approved service-fee policy.

## Implemented measurement contract

Every stream belongs to one Robinhood PoolId and a verified full PoolKey. Indexing starts with a re-read `Initialize` event; a catalogue observation alone does not establish the initialization block. A worker follows `Initialize`, `ModifyLiquidity`, `Swap`, `Donate` and `ProtocolFeeUpdated` from the official PoolManager, ordered by block and log index. Event quantities are integer strings in currency base units. Symbols, decimals and stablecoin assumptions do not define identity or affect this arithmetic.

| Output | Meaning |
|---|---|
| Swap count | Number of core `Swap` events; nonzero swaps are counted separately |
| Gross input, per currency | Sum of negative swap deltas with sign reversed; includes that input's swap fee |
| Output, per currency | Sum of positive swap deltas |
| Absolute turnover, per currency | Input plus output in that one currency's base units |
| Donations | Separate event count and exact amounts; excluded from trading volume |
| Active liquidity | Sum of recorded range liquidity for `tickLower <= tick < tickUpper`, checked against StateView |
| Fee growth | On-chain Q128 counters; reconstructed when a qualified fee ledger exists, diagnostic otherwise |
| Trading LP fees | Core swap-fee portion assigned to LPs, before Q128 distribution rounding; excludes protocol fees and donations |
| Protocol fees | Separately reconstructed per swap step in the input currency's base units |
| Position principal | Sum of each core position's principal, rounded down in currency base units at the snapshot price |
| Unsettled fees | Core position fee liability since its last liquidity change or fee poke; includes allocated donations |
| LP-attributed assets | Reconstructed core token flows excluding protocol allocation, split into principal, unsettled fees and rounding residual |

The two currency turnover figures describe two legs of the same trades. They must not be added together as USD volume. Core swap deltas also do not reconstruct wallet-side transfer taxes, hook adjustments or a user's total transaction costs. Hooked and dynamic-fee pools still require separate operation/accounting qualification. The event sender is the caller of PoolManager, which may be a router or PositionManager; it is not evidence of a distinct trader or NFT owner. ABI layout and event ordering follow Uniswap's [PoolManager interface](https://raw.githubusercontent.com/Uniswap/v4-core/main/src/interfaces/IPoolManager.sol) and [implementation](https://raw.githubusercontent.com/Uniswap/v4-core/main/src/PoolManager.sol).

## Rolling time and freshness

The window is `(snapshot timestamp − 86,400, snapshot timestamp]`, using canonical block timestamps. It is anchored to the last indexed block, not a calendar day or the wall clock at query time. Events exactly at the lower boundary are excluded; events at the snapshot timestamp are included. Same-second blocks retain block/log ordering.

An uninterrupted stream from initialization gives the observed history. If the pool is younger than 24 hours at that snapshot, the response uses `pool_younger_than_window`, reports observed seconds and keeps `completeWindow: false`. A fully covered empty interval has an observed zero swap count; a missing stream returns an unavailable error rather than an empty metric.

The API rechecks the stored block hash against the configured RPC and separately obtains a fresh head. Historical activity remains readable with `freshness: stale`; it cannot be promoted to current 24h data. The initial local freshness threshold is 120 seconds. It is a development threshold, not a calibrated price-oracle or signing limit. A reader never clears history merely because the RPC fails.

## Reconciliation before persistence

The range model replays adds, removals and zero-liquidity-delta fee pokes. Negative resulting range liquidity, invalid alignment, an absent initialization and inconsistent post-swap active liquidity stop the chunk. At its end, reconstructed price, tick, packed protocol fee and active liquidity must match StateView at the same block. Fee-growth counters are read there as diagnostics. Historical state access uses the documented [StateView methods](https://raw.githubusercontent.com/Uniswap/v4-periphery/main/src/lens/StateView.sol).

For hookless fixed-fee pools, each nonzero swap's reported fee is checked against the then-current directional protocol fee and the PoolKey LP fee. In integer pips, the combined rate is `protocol + LP − floor(protocol × LP / 1,000,000)`. Updating the protocol fee later does not change earlier swap rates. This follows Uniswap's [protocol fee calculation](https://raw.githubusercontent.com/Uniswap/v4-core/main/src/libraries/ProtocolFeeLibrary.sol).

Events, the reconstructed model, the on-chain snapshot and the next-block cursor commit together. A confirmed reorg rolls back affected chunks, which removes their events and model snapshots; totals are then recomputed from the retained stream. A missing common checkpoint among the most recent 64 restarts the configured history. If its Initialize anchor no longer exists, the worker reports the missing anchor and stops until that history can be requalified. Identical duplicate logs are ignored; conflicting duplicates abort. Writer serialization, bounded requests, response sizes and per-window event limits are enforced.

Activity checks alone are not proof of complete RPC delivery or a complete pool balance ledger. An omitted roundtrip swap or temporarily added-and-removed position can leave the same final active liquidity. Independent-provider reconciliation remains a dependency. Raw event sender and salt fields now feed the separate position ledger described below; the original aggregate range model retains its narrower scope.

## Trading-fee ledger — implemented in API 0.5.0

`migrations/003_fee_ledger.sql` adds an independent derived ledger with its own methodology version. It does not reinterpret old activity models as reconciled fee data. An explicit bounded worker replays each existing chunk from initialization, verifies the reconstructed activity model and both fee-growth counters, re-reads StateView at the same historical block, and checks canonical block hashes before writing. Fee rows and their checkpoint commit together. Foreign keys remove affected fee records when activity reorg recovery removes their source chunks. Activity can advance independently; until the fee ledger reaches that exact activity tail, fee quantities are unavailable.

The arithmetic is pinned to [v4-core revision 46c6834](https://github.com/Uniswap/v4-core/tree/46c6834698c48bc4a463a86d8420f4eb1d7f3b75). It uses integer tick prices, directional protocol rates, initialized ticks including boundaries with zero net liquidity, uninitialized bitmap word boundaries, changing active liquidity and each step's rounding. Partial exact-input steps retain the contract's net input calculation; deriving all net inputs from final price deltas would be incorrect. Attribution and non-production test references are recorded in [third-party notices](backend/THIRD_PARTY_NOTICES.md).

Swap events omit the original specified amount, exact-input/output mode and price limit. The worker tries equivalent replays using consumed amounts, the observed ending price as a possible limit, and a continuing amount for price-limited empty tails. A candidate must reproduce both event legs, ending sqrt price, tick and liquidity. No matching result, differing fee results among matches, or a work-budget overflow makes accounting unavailable; it does not fall back to nominal-rate multiplication. This conservative reconstruction is qualified against the original Pool library and live snapshots, not claimed to decode every possible swap. Hooks and dynamic-fee pools currently require an accounting adapter; generic token and pool reads continue to work.

Each step splits protocol fees before adding the LP contribution to global Q128 growth, with uint256 wrapping. Donations contribute to growth but remain separate from trading LP fees. Adds, removals and fee pokes change the activity state used for subsequent swaps; they do not themselves create trading fees. Exact counter reconciliation is additional evidence, not proof of complete RPC delivery or of per-position collectible balances.

`window24h.lpFeesRaw` and `protocolFeesRaw` are currency0/currency1 integer-string pairs over the existing timestamp interval. `fees.accounting` exposes cumulative quantities since initialization, version, scope and status. `lpFeesBasis` explicitly says `core_trading_fee_before_Q128_distribution_rounding`; `isCollectedAmount` and `isDominoServiceFee` are false. API 0.6.0 provides separate position settlement and residual accounting below. Aggregate trading-fee measurements cannot serve as the basis for billing an owner or authorizing a transaction.

The [fee qualification report](reports/FEE_ACCOUNTING_QUALIFICATION.md) records 139 passing tests, 1,024 independent native swap-step comparisons, four native Pool sequences and exact reconciliation of seven historical chunks across two real Robinhood pools. Those live samples remain younger than 24 hours at their snapshots; their later HTTP reads are correctly marked stale.

## Core positions and attributed assets — implemented in API 0.6.0

Within a PoolId, identity is `keccak256(packed core owner, lower tick, upper tick, salt)`. The core owner is the PoolManager caller from `ModifyLiquidity`, often PositionManager. It is not the NFT holder. Salt is opaque; the ledger does not assume it is an NFT number. Equal ranges with different owners or salts retain separate liquidity and fee debt.

The position model tracks initialized and cleared tick state, fee growth outside each boundary, position liquidity and last fee growth inside. Swap reconstruction now also requires agreement on growth at each initialized crossing. Identical final trading-fee totals are insufficient when crossing histories differ. Position settlement uses liquidity before each change. Tick initialization, fee settlement, clearing, and reopening preserve the native ordering and uint256 wrapping. A fee poke settles debt without changing principal. These rules are checked against the pinned original [Pool](https://github.com/Uniswap/v4-core/blob/46c6834698c48bc4a463a86d8420f4eb1d7f3b75/src/libraries/Pool.sol) and [Position](https://github.com/Uniswap/v4-core/blob/46c6834698c48bc4a463a86d8420f4eb1d7f3b75/src/libraries/Position.sol) implementations.

Pool-attributed flow starts at zero at initialization. Principal additions increase it; removals and settled position fees decrease it. Swap caller deltas change it with the opposite sign, subtracting the protocol allocation. Donations increase it. For each currency, the published identity is `lpAssetsRaw = principalRaw + unsettledFeesRaw + roundingResidualRaw`; negative reconstructed assets or residuals fail qualification. This measures core accounting attribution, not a token balance read from the shared manager. The residual records smallest-unit arithmetic effects across deposits, swaps, distribution and settlement. It does not establish a distributable position claim. Principal deposited/withdrawn fields are gross core principal flows, not external wallet funding or investor P&L.

Every position chunk depends on the corresponding reconciled fee chunk. Before committing, the worker rechecks the full pool snapshot, every known position's liquidity and last fee-growth values, every distinct range's growth inside, and every known tick's gross/net liquidity and growth outside, including cleared ticks and closed positions. It uses [StateView getters](https://raw.githubusercontent.com/Uniswap/v4-periphery/main/src/lens/StateView.sol) at the same canonical historical block. Checkpoint, reconciliation metadata and per-modification settlement rows commit together. Rewinding source activity or fees removes dependent position data. A position ledger behind the current activity tail remains unavailable.

`liquidity.positionAccounting` exposes aggregates in the activity route. `POST /v1/read/pool-positions` adds bounded individual core records with the same canonicality/freshness check. `nftOwnershipResolved`, `isWalletBalance` and `isWithdrawalQuote` remain false. The worker initially permits 128 lifetime core identities and 256 known boundaries per pool, 2,000 events and 100,000 candidate swap steps per chunk, with bounded RPC requests/deadlines. Exceeding capacity requires a larger reviewed reconciliation workflow; it does not silently truncate positions. Hooks and dynamic fees require an adapter.

The [position qualification report](reports/POSITION_ACCOUNTING_QUALIFICATION.md) records 161 passing tests, an original-Pool sequence covering distinct owners/salts, fee pokes, partial removals, full closure and reopening, seven real historical checkpoints and actual HTTP reads. Trading fees, position liabilities and core token flows are separately named; none enables owner billing or execution.

## Event-time capital and USD calculation — API 0.7.0

`005_capital_prices.sql` adds capital checkpoints and an after-event asset record for every source event. `CapitalIndexer` independently replays the position model with an observer, compares its complete final model and activity state, repeats position/tick/inside-growth checks, and commits event history with its checkpoint. Source reorg deletion cascades to the dependent capital records. A missing event, incomplete checkpoint stream or mismatching final assets is unavailable. Empty chunks extend time coverage without inventing capital changes.

Capital is a right-continuous step function of canonical block timestamp: the last event among blocks/logs at the same timestamp determines the balance until the next timestamp. The state at the start of the window is the last event at or before that boundary. A change at the final timestamp affects current TVL but has zero duration in the preceding time average. The exact raw integral is `sum(assetRaw × elapsedSeconds)`, reported with its denominator in seconds. In-range and out-of-range positions contribute their attributed assets. LP assets include principal, unsettled fees and the explicitly separated rounding residual; protocol-owned amounts are excluded. Cumulative principal flows remain gross core flows, not investor deposits or P&L.

The USD engine integrates these balances together with changes in qualified external prices. It uses exact rational arithmetic and only rounds the published decimal strings to 18 places. A qualified price is carried forward causally for at most its approved age (initial upper bound 300 seconds). Future observations never fill earlier gaps. The integrator splits at capital events, price updates and expiry boundaries; a gap anywhere, including between asset events, invalidates the dollar result. For each swap, gross input is valued once at its timestamp. LP trading allocations are valued separately; donations, liquidity flows and protocol fees do not become trading revenue.

For a complete trailing day and positive average TVL, `feeAprPercent = 100 × 365 × tradingLpFeesUsd / timeWeightedAverageTvlUsd`. A younger pool retains its observed interval with APR unavailable; zero average capital never yields an infinite APR. Historical freshness is separate from coverage. `/v1/read/pool-metrics` reports the raw history and price-quality diagnostics even while dollar fields are unavailable. No recommendation or signing authority follows from a calculated metric.

## External price observations and current qualification gap

`AlchemyHistorical` queries a Robinhood ERC-20 using its exact network/address. Only native ETH uses the explicitly defined native-asset-to-ETH mapping; WETH, USDG and arbitrary symbols are never silently aliased. A bounded invocation retrieves at most a day plus its boundary margin at five-minute intervals. The stored identity includes chain, currency address, source, observation timestamp, retrieval time and provenance. Equal observations resume idempotently; a conflicting revision stops the transaction instead of rewriting history. Provider failure preserves existing observations and capital checkpoints.

The real qualification obtained 12 native-ETH price points. The same endpoint returned HTTP 400 for all three ERC-20 addresses in the two-pool sample, and a bounded diagnostic confirmed an unsupported-network response for `robinhood-mainnet`. Working Robinhood RPC/token inventory access does not establish Prices API coverage. The provider's [historical endpoint](https://www.alchemy.com/docs/data/prices-api/prices-api-endpoints/prices-api-endpoints/get-historical-token-prices) documents symbol or network/address lookup, while its [FAQ](https://www.alchemy.com/docs/reference/prices-api-faq) distinguishes aggregate exchange sources; neither response alone proves independence from the pool being measured or whether a bucket timestamp is a point price or an interval statistic.

The production qualification registry is intentionally empty. Provider observations and HTTP requests cannot grant themselves qualification. Native ETH points remain `observed_unqualified`; unavailable ERC-20 history remains `unavailable`. A reviewed source adapter must establish currency identity and decimals throughout the interval, independent price integrity, observation-time semantics and coverage before its data enters dollar calculations. Unit/integration test qualifications are synthetic fixtures only. The backend can calculate TVL and APR when that contract is satisfied, but this milestone does not report qualified live dollar TVL or APR.

## NFT ownership and current position reads — API 0.7.0

The official PositionManager adapter reads `getPoolAndPositionInfo`, reconstructs the full PoolId from all five PoolKey fields, checks the stored 200-bit lookup prefix and signed range ticks, then verifies `ownerOf` and liquidity at the same block. Only this manager's documented `bytes32(tokenId)` salt mapping is used; other core callers require their own adapter. `/v1/read/pool-positions` adds an `nft` object to each known record, at the ledger's historical snapshot. A mixed or empty set is not claimed to have fully resolved ownership.

`POST /v1/read/nft-positions` accepts one to ten unique uint256 IDs as decimal strings, with an optional bounded historical block. Without a block it reads a fresh head. It compares PositionManager liquidity with StateView core liquidity, then returns principal and current unsettled fees. Owner reads are not cached: a subsequent transfer is reflected on the next fresh query. A cleared position-info record has no resolved owner; RPC failure is an error, never proof of burn. A closed but unburned NFT can still have an owner and zero liquidity. Block hashes are rechecked after all calls.

The adapter follows Uniswap's [PositionManager](https://raw.githubusercontent.com/Uniswap/v4-periphery/main/src/PositionManager.sol) and [PositionInfoLibrary](https://raw.githubusercontent.com/Uniswap/v4-periphery/main/src/libraries/PositionInfoLibrary.sol). It verifies read identity and state, not wallet control, approvals, compatibility of a withdrawal path, transfer-tax behavior or operator authority. Past settled fees stay in the pool/core ledger and are never attributed to the current NFT owner. Discovering every NFT in a wallet and a persisted ERC-721 transfer/event index remain separate work.

## Remaining valuation and execution gates

**Owner and withdrawal eligibility:** build wallet-NFT inventory/watchlists and authenticated owner sessions on the new pinned ownership reads; persist transfer history where needed and verify permissions, native-currency behavior, token compatibility and actual settlement paths. The core ledger does not attribute past financial entitlements to an authenticated user or simulate a valid owner's withdrawal transaction.

**Historical TVL:** event-timestamp attributed-asset history and the time-weighted engine are implemented. Broaden indexed intervals and qualify token decimals and independent historical prices before publishing dollar TVL. Neither the shared manager's balance nor active liquidity is a substitute. Hook-managed external liquidity requires a reviewed adapter.

**USD valuation:** require validated currency identity and decimals plus timestamp-aligned, qualified prices. Do not assume USDG or another token is worth $1 from its symbol. Do not let the pool being ranked serve as its sole price-integrity check. The planned once-per-trade convention is gross input valued at that swap's timestamp; paired-currency amounts remain separate checks, not another counted trade. Price provenance, coverage and quality thresholds must pass qualification before this field becomes available.

**Fee APR:** retain the approved historical pool formula: `100 × 365 × trading LP fees in the trailing 24h / time-weighted average pool TVL over the same interval`. Use the same valuation convention and complete, fresh coverage for numerator and denominator. This is a pool trading-fee statistic, not position APR, APY, total return or a promise of profit. Domino's 2% automation service fee remains a separate charge with its own earned-fee basis.

Before enabling comparisons or suggestions, qualify an established pool with at least 24 hours of reconciled history and qualified prices, then calibrate the activity/depth filters in [onboarding](ONBOARDING_AND_POOL_DISCOVERY.md). The current small live samples qualify historical core accounting; their age and freshness do not establish a full trailing day or a return statistic.
