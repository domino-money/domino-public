# points-v1

Season 1's points for the app: the owner's points campaign of 6–7 Nov 2026 (`docs/points/POINTS.md`). It is a closed
contract between the private listener (`backend/points_api.py`), the bridge Worker
(`bridge/src/points-worker.mjs`) and the app. Seeing points needs the wallet's sign-in: both routes answer for the
SIWE session's wallet, and no request names a wallet.

| Route | Request | Answer |
| --- | --- | --- |
| `points` | `{}` | The season and the latest snapshot (or `null` before the first one). The wallet's entry: points, points for use, referral points, revenue in USD by kind, its referrer, how many wallets it referred. A wallet the snapshot does not hold answers zero |
| `link` | `{referrer, issuedAt, signature}` | `{status: "recorded" or "existing", referee, referrer}`. The first link of a season holds: a later one answers the first referrer |

**The link.** The app builds the text with `referralText(season, referee, referrer, issuedAt)`:
- `season` comes from a `points` answer;
- `referee` is the signed-in wallet;
- `referrer` comes from `?ref=`;
- `issuedAt` is the current Unix time.

The wallet signs that text with `personal_sign`. The listener rebuilds the same text, and the signer must be the
signed-in wallet. `fixtures/signed-text.json` pins the text and a signature.

**Refused,** with these codes:
- `referral_self`;
- `referral_wallet_excluded`: the team, Domino's roles, the governance Safe's owners, the public test accounts;
- `referral_season_closed`;
- `referral_message_not_fresh`: more than 10 minutes from the listener's clock;
- `referral_signature_invalid`;
- `referral_signature_mismatch`.

**Numbers.** Points are decimal strings with six places, and USD with eighteen. `points = usagePoints +
referralPoints` exactly, and the runtime holds every answer to it.

**Transport.** It is the authenticated families' transport (`authenticated-worker.mjs`):
- the browser POSTs `/api/points/v1/<route>`;
- the Worker forwards it to the listener's `/internal/points/v1/<route>`, with the session and CSRF headers and the
  `X-Domino-Points-Contract` header;
- the Worker is off until `POINTS_BRIDGE_ENABLED` is exactly `"true"`.

Files: `schemas/`, `types.ts`, `runtime.d.mts`, `schema-data.mjs`, `fixtures/` and `manifest.json` are generated by
`scripts/export-points-contract.py` (`--check` in CI). `runtime.mjs`, this README and `consumer.test.mjs` are written
by hand, and the manifest hashes them.
