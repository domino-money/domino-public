# Execution Cloudflare preflight

`Inspect execution Cloudflare path` is a manual, read-only GitHub Actions workflow. Dispatch it from `main` with `source_sha` equal to that exact main commit. It uses the existing repository `CLOUDFLARE_API_TOKEN` secret and `CLOUDFLARE_ACCOUNT_ID` variable; neither is written to disk or printed. The result consists only of booleans. No Access policy, service token, DNS record, Tunnel route, Worker binding or financial capability is created or changed.

The preflight inventories Access applications without a domain filter at both account and `domino.money` zone scope. This detects path-specific and wildcard applications that could override the application at `vm-execution.domino.money` for `/internal/execution/v1/{availability,status,list}`. `accountAccessAppsReadable` and `zoneAccessAppsReadable` report the two inventories separately; `executionRouteExclusive` requires both complete inventories and no competing application covering those paths. The execution Worker uses `vm-execution.domino.money`, so a service token admitted only to `vm-session.domino.money` cannot serve it. `executionAppDistinct` additionally requires different application IDs and audiences. A false result is a finding to resolve, not an instruction to reuse the session application. The expected execution status listener is read-only; this workflow does not contact it.

The remaining booleans say whether this API credential can **read** Access service-token metadata, the execution Worker's metadata and secret **names**, the production Tunnel configuration, the `domino.money` zone and an exact-name DNS record. `executionWorkerDisabled` checks the deployed `EXECUTION_BRIDGE_ENABLED=false` setting. `executionBroadAccessAbsent` is true only when every policy in the complete execution inventory is either Block or Service Auth whose **every** Include selector names a specific service token. A Service Auth policy with Require or Exclude selectors needs separate review and remains false. Allow, Bypass, mixed Include selectors, unknown decisions and malformed policies also make it false. `executionSpecificServiceAuthPresent` additionally requires at least one such Service Auth policy. `executionTunnelHostPresent` and `executionDnsPresent` check only hostname presence, not route or DNS correctness. No IDs, audiences, origins, policy bodies, tunnel configuration, DNS values or API error bodies enter the log.

A false `dnsRecordsReadable` value can also mean that this token lacks Zone Read, so the script could not discover the zone ID before testing DNS Read; it does not prove DNS Read was denied. Likewise, a successful GET does not establish **write** permission. Provisioning a distinct execution service token later would require account-scoped Access Service Tokens Write, Access Apps and Policies Write and Workers Scripts Write in addition to suitable reads. The existing token's last recorded inspection in [CLOUDFLARE_RELEASE_TOKEN.md](CLOUDFLARE_RELEASE_TOKEN.md) could read Pages but not Workers or Tunnel; its current scope must be measured, not assumed.

All requests use GET, an 8-second per-call timeout and a 512 kB response limit. Only the fixed account, discovered exact zone and bounded numeric Access page targets are queried. Account and zone Access inventories require consistent page metadata and all pages, capped at ten pages of 100 applications each; a larger inventory fails closed for manual review. Zone and policy checks require `page=1` and `total_pages=1`. Missing or inconsistent metadata, an API refusal, malformed answer or partial inventory yields false for the affected check. The workflow remains useful even when the token lacks permissions, because every family is inspected independently.

Cloudflare API references: [Access applications](https://developers.cloudflare.com/api/resources/zero_trust/subresources/access/subresources/applications/methods/list/), [application path precedence](https://developers.cloudflare.com/cloudflare-one/access-controls/policies/app-paths/), [service tokens](https://developers.cloudflare.com/api/resources/zero_trust/subresources/access/subresources/service_tokens/methods/list/), [Worker settings](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/script_and_version_settings/methods/get/), [Tunnel configuration](https://developers.cloudflare.com/api/resources/zero_trust/subresources/tunnels/subresources/cloudflared/subresources/configurations/methods/get/), [zones](https://developers.cloudflare.com/api/resources/zones/methods/list/) and [DNS records](https://developers.cloudflare.com/api/resources/dns/subresources/records/methods/list/).
