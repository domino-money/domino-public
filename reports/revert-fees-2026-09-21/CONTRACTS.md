# Revert automation fee contracts — source review, 2026-09-21

**The inspected contracts do not implement one universal “2% plus a swap fee” rule.** Current-source `SelfCompoundor` has a fixed zero protocol reward. `AutoCompound` starts at 2% of tokens actually added to liquidity, after any internal swap. AutoRange/AutoExit range-change/exit rewards are selected by the executor within a position-owner-approved cap; their fee basis can include principal when the owner selects that mode. Native transaction gas is paid initially by the transaction sender. None of these inspected fee paths measures gas spent and then reimburses that exact amount.

This is a source and documentation comparison, not a contract security audit, deployment attestation, or live fee quote. Official websites were consulted on 2026-09-21. Official repositories were cloned only into `/tmp` and read; no third-party code, tests, deployment scripts, wallets or transactions were run. Only this report was added to Domino.

## Fee map

Write `r = rewardX64 / 2^64`. Integer calculations truncate in the contracts.

| Path | Source charge basis | Who fixes the rate/cap? | Where the reward goes |
| --- | --- | --- | --- |
| SelfCompoundor | Zero protocol charge: `totalRewardX64=0` | Compile-time constant; no setter | No calculated reward; owner can sweep residual ERC-20 balances |
| AutoCompound v3 | `floor(amountAdded_i × r)` for each token, after swap | Starts near 2%; contract owner can only lower current rate | Separate protocol accounting bucket; designated withdrawer withdraws it |
| AutoRange `autoCompound` | Same added-token formula | Separate global rate starts near 2%, owner can only lower it; position must enable auto-compounding | Retained token reward, withdrawable by designated withdrawer |
| AutoRange range change, `onlyFees=true` | `floor(collectedFee_i × r)`, before swap/mint | Position owner sets `maxRewardX64`; executor supplies `rewardX64 ≤ cap` | Retained token reward |
| AutoRange range change, `onlyFees=false` | `floor(newPositionAdded_i × r)`; this can include principal | Same position cap/executor choice | Retained token reward |
| AutoExit, `onlyFees=true` | `floor(collectedFee_i × r)` before optional swap | Same position cap/executor choice | Retained token reward |
| AutoExit, whole-position mode | Without swap: percentage of both collected totals. With swap: percentage of final target-token balance | Same position cap/executor choice | Retained token reward |

The [product documentation](https://docs.revert.finance/revert/auto-compounder) describes auto-compounding as a 2% performance fee compensating protocol and transaction execution. AutoRange and AutoExit documentation instead describe 0.15% of position assets or 2% of uncollected fees, with an additional user-selected gas budget and unspent amounts retained/returned. These are distinct product policies, not interchangeable source constants. [AutoRange policy](https://docs.revert.finance/revert/auto-range), [AutoExit policy](https://docs.revert.finance/revert/auto-exit).

### AutoCompound v3: 2% of added liquidity, not 2% of gross available tokens

The [initializer](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/transformers/AutoCompound.sol#L47-L50) sets the Q64 approximation of 2%; [the setter](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/transformers/AutoCompound.sol#L251-L260) disallows increases above the current value. This is a decreasing ceiling, not an owner-controlled arbitrary fee.

After collection and any swap, the contract makes at most `A_i/(1+r)` available to `increaseLiquidity`, charges `r × actualAdded_i`, and credits the remaining tokens to that NFT's balance. The protocol reward uses token-ID bucket zero. [Calculation and accounting](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/transformers/AutoCompound.sol#L161-L187).

Ignoring integer rounding and token-ratio leftovers, 100 units available at 2% produce about 98.039216 added and 1.960784 reward: the reward is 2% of the added amount, approximately **1.960784% of the gross available amount**. Domino's 2% of gross consumed earned fees is a different denominator. A fair comparison must show denominator and swap realization costs, not merely compare two labels saying “2%.”

Execution is restricted to approved protocol operators or validated vault transformations. It collects tokens owed by the position manager and adds previously stored leftovers for the same NFT. [Authority, collection and carried balances](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/transformers/AutoCompound.sol#L91-L127). There is no separate current-source executor/protocol split inside `execute`: the complete reward is recorded as protocol balance. [Withdrawal only from bucket zero](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/transformers/AutoCompound.sol#L228-L248). The offchain arrangement that pays operators or converts these tokens to ETH is not proven by this code.

### SelfCompoundor: zero service reward, sender-paid gas and same-transaction return

The [source constants](https://github.com/revert-finance/compoundor/blob/800d0a6462be0bf78a418f3d58dd407eeadef173/contracts/SelfCompoundor.sol#L18-L35) fix reward at zero, TWAP period at 60 seconds and maximum tick difference at 100. There is no fee setter. Fee-calculation scaffolding remains in the source but multiplication by the zero constant produces zero; comments describing retained protocol rewards do not override the executable value.

The user safely transfers an NFT to the helper, which validates that the caller is the configured position manager, compounds, and safely returns the NFT to the transfer's `from` address during the same transaction. Empty receiver data defaults to performing a swap; explicit receiver data can disable it. [Receiver path](https://github.com/revert-finance/compoundor/blob/800d0a6462be0bf78a418f3d58dd407eeadef173/contracts/SelfCompoundor.sol#L85-L109). Liquidity additions use actual available amounts, approvals are reset, and both token leftovers are sent back to `from`. [Add, zero reward and refunds](https://github.com/revert-finance/compoundor/blob/800d0a6462be0bf78a418f3d58dd407eeadef173/contracts/SelfCompoundor.sol#L164-L211).

The transaction submitter still pays native gas, and any swap still incurs pool trading costs. Zero protocol reward is not zero total cost. The contract owner can [sweep its ERC-20 balances](https://github.com/revert-finance/compoundor/blob/800d0a6462be0bf78a418f3d58dd407eeadef173/contracts/SelfCompoundor.sol#L67-L82), so accidentally transferred tokens are not segregated user deposits. This source conclusion does not itself verify the Robinhood address's deployed bytecode.

### AutoRange: range-change reward and auto-compound reward are separate controls

For range changes, the owner authorizes `onlyFees` and a `maxRewardX64` in the position config; the protocol executor chooses an actual rate no higher than it. [Config structure](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/transformers/AutoRange.sol#L52-L65), [execution cap](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/transformers/AutoRange.sol#L133-L162), [owner configuration](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/transformers/AutoRange.sol#L464-L487). No universal 0.15% or 2% cap is enforced on this path: its bound is the owner's uint64/Q64 cap, representationally below 100%. A user interface must not confuse that general bound with the product's advertised fee schedule.

In fee-only mode the reward is removed from collected fees before swapping. In position-assets mode the reserve is again `available/(1+r)`, and reward is computed from what actually enters the successor. [Mint reserve](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/transformers/AutoRange.sol#L219-L246), [reward and refunds](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/transformers/AutoRange.sol#L248-L294). Principal can therefore be a fee source by express configuration. The successor NFT goes to the original owner/vault; leftovers go to the beneficial owner, WETH may be unwrapped, and configuration is copied to the successor then cleared for the old NFT.

The separate `autoCompound` method requires `config.autoCompound`, uses a global `totalRewardX64`, and returns leftovers rather than carrying them as AutoCompound does. Its fee is **not governed by the range-change `maxRewardX64` field**. [Enablement](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/transformers/AutoRange.sol#L353-L367), [calculation/refunds](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/transformers/AutoRange.sol#L406-L450), [global rate reduction](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/transformers/AutoRange.sol#L490-L499).

### AutoExit: fee source and swap direction alter the base

Only a configured protocol operator may execute; active configuration and the owner's reward cap must pass. [Authority and cap](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/automators/AutoExit.sol#L101-L140). Position configuration is set by the NFT owner. [Owner check](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/automators/AutoExit.sol#L219-L246).

Fee-only mode deducts from both collected fee amounts before an optional swap. Whole-position mode without a swap deducts from both asset totals. With a swap, whole-position mode charges only the resulting target-token balance, which includes any preexisting target tokens plus swap proceeds; unconverted input leftovers are returned. There is one configured reward calculation, not an exit reward followed by a separate Revert swap percentage. [Swap and fee branches](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/automators/AutoExit.sol#L143-L198). Remaining tokens go to the NFT owner, configuration is deleted, and full liquidity has been removed; the original NFT is not replaced. [Return and cleanup](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/automators/AutoExit.sol#L201-L216).

## Swaps, gas and failure accounting

**No additional Revert percentage on internal swap volume was found in these fee paths.** That is a scoped code conclusion, not a claim that every router quote is free of integrator fees. AutoCompound and AutoRange's compound method swap directly against the position pool. Range changes and AutoExit use an immutable configured Universal Router or 0x AllowanceHolder and offchain-supplied instructions. The shared router code measures actual input/output balance deltas, checks minimum output and resets the 0x allowance. [Router settlement](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/utils/Swapper.sol#L66-L109). Pool fees, price impact, slippage and any charges encoded by the external route affect realized proceeds. The companion assisted-swap review must analyze that route separately; V3Utils pricing cannot be assumed to run again inside every automator swap.

AutoCompound checks spot versus TWAP **before** the swap, disables the swap when the check fails, and uses minimum output zero for its direct pool call. It may still compound available tokens without swapping. [Swap behavior](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/transformers/AutoCompound.sol#L133-L158). SelfCompoundor instead reverts when required TWAP history/deviation fails and also calls its router with zero minimum output. [Self TWAP check](https://github.com/revert-finance/compoundor/blob/800d0a6462be0bf78a418f3d58dd407eeadef173/contracts/SelfCompoundor.sol#L267-L278), [swap call](https://github.com/revert-finance/compoundor/blob/800d0a6462be0bf78a418f3d58dd407eeadef173/contracts/SelfCompoundor.sol#L331-L333). A pre-swap TWAP check is not a mathematical bound on the execution's own price impact; comments claiming sandwich prevention should not be generalized into a guarantee.

Range changes validate TWAP even without a swap; AutoExit invokes swap price validation when it actually swaps. Their output floor combines spot price with owner-configured price tolerance. [Validation formula](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/automators/Automator.sol#L127-L150). Protocol owner controls operators, withdrawer and oracle configuration; source enforces at least 60 seconds and at most 200 ticks. Despite a comment suggesting only tightening, the setter checks these absolute bounds rather than comparing with prior settings. [Administrative controls](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/automators/Automator.sol#L52-L84).

Rewards are retained in token balances and later withdrawn; they are not automatic same-transaction native-ETH gas reimbursement to the executor. Range/Exit use the [designated withdrawer](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/automators/Automator.sol#L86-L125). There is no `gasleft()`/`tx.gasprice` calculation in the inspected reward paths. An executor can choose a rate below the owner's cap; the contract does not prove that the difference between cap and chosen rate equals unused actual gas. The documentation's gas-budget language describes an operational policy that needs separate verification.

An uncaught revert rolls back collection, swaps, liquidity mutations, calculated rewards and refunds in that transaction, but the submitter still pays network gas. Return failures can cause such a revert: native refunds unwrap WETH then call the recipient, reverting on failure. [Refund mechanics](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/automators/Automator.sol#L212-L229). Profitability therefore depends on failed attempts, token-to-ETH realization, sufficient executor ETH and successful execution volume; a percentage reward is not guaranteed gas coverage.

## Legacy Compoundor is a different model

The deprecated v1 has an initial 2% total reward, half initially assigned to the caller and half to the protocol; total can only decrease, while the owner can alter the split within it. [Defaults/setter](https://github.com/revert-finance/compoundor/blob/800d0a6462be0bf78a418f3d58dd407eeadef173/contracts/Compoundor.sol#L33-L74). Anyone can compound deposited NFTs. The recorded NFT owner is exempt from the reward when calling directly. Rewards can remain in both currencies or be denominated in one using the pool price, capped by available leftovers; then caller and protocol balances are credited. [Fee calculation and distribution](https://github.com/revert-finance/compoundor/blob/800d0a6462be0bf78a418f3d58dd407eeadef173/contracts/Compoundor.sol#L197-L246).

This version holds deposited NFTs and owner/token balances, including leftovers shared across that owner's positions in the same token. Owners can withdraw the NFT and balances. [Withdrawal path](https://github.com/revert-finance/compoundor/blob/800d0a6462be0bf78a418f3d58dd407eeadef173/contracts/Compoundor.sol#L303-L338). Those custody and public-executor properties must not be attributed to current AutoCompound's approval-based operator model. The [v1 FAQ](https://docs.revert.finance/revert/resources/auto-compounder-v1-faq) explicitly identifies itself as deprecated; its historical “100× gas” threshold is not evidence of today's v3 bot policy or a current Robinhood gas estimate.

## Useful distinctions for Domino

1. **Separate self-service, automation and assisted swaps.** Revert's zero-fee SelfCompoundor and paid auto-compounding show that they are distinct products. They do not authorize changing Domino's approved tariff or combining a 2% automation fee with another 2% internal-swap charge.
2. **Specify gross versus net charge bases and lot provenance.** Revert's added-token denominator differs from Domino's consumed-earned-fee denominator. More subtly, position-manager `collect` is not a provenance ledger: it can include previously decreased-but-uncollected principal. Range/Exit infer fees as `collected − amounts returned by this execution's decreaseLiquidity`, not through historical lot tracking. [Inference in code](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/automators/Automator.sol#L188-L209). That observation describes a precondition-sensitive accounting limit, not a demonstrated exploit. Domino must retain its stronger original-fee/principal/already-charged distinctions rather than copying this inference.
3. **A fee cap and an actual-cost reimbursement are different mechanisms.** A user-approved percentage can fund automation but permits that percentage independent of actual gas. Domino's company treasury can convert already-earned revenue into ETH without adopting Revert's principal-funded mode or adding a customer gas debit.
4. **Keep chargeable consumption separate from leftovers.** Current AutoCompound segregates leftovers by NFT and protocol fees in a distinct bucket; owners can withdraw their own balances. [Owner withdrawal](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/src/transformers/AutoCompound.sol#L202-L225). AutoRange/SelfCompoundor return leftovers immediately. Both patterns need explicit accounting and recovery rather than treating the contract's full token balance as protocol revenue.
5. **Preserve stronger execution bounds.** Balance-delta settlement, bounded user fee caps, role separation and allowance cleanup are useful concepts. Zero-minimum-output swaps, broad NFT approvals, unrestricted router instruction formats and an implicit assumption that TWAP alone guarantees execution quality should not be transplanted into Domino. Scope, amount, recipient, identity and price limits remain independently necessary.

Code reuse also needs version-specific license review: Compoundor declares MIT; Lend files declare BUSL-1.1, and its [license](https://github.com/revert-finance/lend/blob/7e85a81ac97663a3a731f6d6f07f14d774962a6e/LICENSE) records a change date and GPL change license. This report reuses no third-party implementation. It establishes mechanisms and differences; exact live fees and executable integration require deployment/runtime verification, current parameter reads, account permissions and fresh economic quotes.
