# Milestone 1 — implementation status

9 September 2026. Scope: the first reviewable product package, not a production financial launch.

## Implemented

- English web workbench in the approved Tangerine palette: a collection of rounded position cards, light/dark appearance, a four-step creation dialog, compact card management and fee-scenario dialogs, and compact Activity cards with signed, semantic amounts and receipt dialogs. Receipt tabs preserve funding provenance, fee basis, gas, routing and historical policy; exact precision is optional. Existing local positions and receipts are preserved.
- Concentrated-liquidity scenario math, showing token/stable composition and the comparison with holding the initial assets. Assumptions remain visible.
- Exact microdollar cost accounting in TypeScript and Python, sharing fixture cases. Only consumed fee balances are charged; the rest remain available.
- Reinvestment policy version 2 uses all eligible balanced fees, removing the inherited 15% addition cap. The UI explains waiting fees; older receipts retain their original policy and can supply balances to new scenarios.
- Server-side cost-preview endpoint with strict fields, decimal strings, a 4 KiB request limit, and explicit simulation-only capabilities.
- Practice-state validation, cross-tab storage synchronization, pending-scenario state-change detection, and pause behavior.
- Isolated Solidity fee-split library and a draft public-vault interface. The interface has no deployable vault implementation.
- Candidate PostgreSQL schema for owner-bound sequences, fee provenance, execution intents, global signer nonces and forced tenant isolation.
- Read-only historical-rate sensitivity report, using the recorded observation log and hypothetical gas. The report excludes wallet addresses, token IDs and raw transaction data.
- Independent read-only Robinhood discovery module and bounded CLI: provider candidate filtering, complete PoolKey verification, pinned-block pool/token reads, address-list balances and an inventory-provider probe. The [qualification report](reports/DISCOVERY_QUALIFICATION.md) records 17 verified MARLIN v4 candidates and successful three-currency balance reads; full wallet enumeration returned HTTP 403. Provider metrics remain unreconciled, with APR, suggestions and execution disabled.
- Local FastAPI read service with strict request fields, bounded reads, Alchemy candidate pagination, address fallback and exact on-chain balances. A hidden-input terminal configurator saves the new backend's provider access locally. The [HTTP qualification](reports/READ_API_QUALIFICATION.md) records 12 Alchemy token candidates, 13 verified balances including ETH and 17 verified pools. This resolves the earlier explorer-access obstacle for the sampled wallet; it does not establish complete provider coverage.
- Generic token lookup independent of the pool provider, optional metadata with no assumed decimals, legacy bytes32 symbols, explicit no-contract states and direct PoolId verification. Missing metadata no longer erases readable raw balances or verified pool identity. API 0.2.0 uses wallet/pool envelope version 2; no token admission list is embedded in the runtime. The expanded backend suite has 65 passing tests; real-token evidence and limits are recorded in [generic qualification](reports/GENERIC_TOKEN_QUALIFICATION.md).
- API 0.3.0 adds a persistent public PostgreSQL catalogue, direct Initialize-event indexing, atomic checkpoints, confirmed-reorg rollback/replay, revision-bound pages and pair filtering. The [catalogue qualification](reports/CATALOGUE_QUALIFICATION.md) records 217 pool identities and 135 currency addresses from 42 revalidated observations plus 175 events across 6,000 blocks. WETH/USDG and a newly indexed pair are found automatically from either currency and freshly verified. Database restart preserves data; backup/restore, reader grants and concurrency are tested. The full backend suite now passes 92 tests, including 15 using PostgreSQL. This is partial public-market coverage, not authenticated account persistence.
- API 0.4.0 adds persistent core-pool activity, raw rolling swap quantities, donation separation, event-ordered protocol rates and range-liquidity reconstruction checked against StateView. The [activity qualification](reports/ACTIVITY_QUALIFICATION.md) records 34,082 indexed blocks for one pool and 10,000 for another, with process resume, bounded catch-up and actual HTTP reads. The full suite now passes 120 tests, including 29 against PostgreSQL. These samples are younger than 24 hours and do not qualify a full-day financial metric; USD volume, LP fee totals, TVL and APR remain unavailable pending the [accounting/valuation work](METRICS_METHODOLOGY.md).

- API 0.5.0 adds independent versioned trading-fee reconstruction for hookless fixed-fee pools, per-step protocol deductions, donation separation and exact global growth reconciliation. [Fee qualification](reports/FEE_ACCOUNTING_QUALIFICATION.md) records seven reconciled historical chunks across two Robinhood pools and actual HTTP fee reads. All 139 tests pass, including 37 PostgreSQL tests and native v4 differential tests covering 1,024 swap steps, 128 tick roundtrips and four Pool sequences. These are core trading-fee allocations before Q128 distribution rounding; collectible position balances, TVL, USD prices and full-day APR remain unqualified.

- API 0.6.0 adds independently reconciled core-position principal, unsettled fees, settlements, tick state and pool-attributed token flow, with a bounded `/v1/read/pool-positions` route. [Position qualification](reports/POSITION_ACCOUNTING_QUALIFICATION.md) records seven real historical checkpoints, actual HTTP reads and 161 passing tests, including 49 PostgreSQL tests and three native EVM methods. Core owner/range/salt identity is preserved across removal and reopening. Dollar valuation, complete event-time averages, NFT ownership and financial execution remain separate work.

- API 0.7.0 adds event-time capital and raw time integrals, persisted external prices, a conditional exact TVL/volume/fee-APR engine, and pinned official PositionManager NFT ownership with current principal/unsettled-fee reads. [Capital/price/NFT qualification](reports/CAPITAL_PRICES_NFT_QUALIFICATION.md) records 200 passing tests, seven reconciled real capital checkpoints and the external price limitation. The Alchemy Prices API returns native ETH history but rejects Robinhood address queries. No production price source is qualified, so live dollar TVL/APR remain unavailable. NFT ownership reads do not implement wallet authentication, wallet-wide NFT enumeration or private accounts.
- Saved the [home infrastructure study](HOME_INFRASTRUCTURE_STUDY.md) for later deployment planning; no home machines were accessed or provisioned.

## Verification scope

The [reinvestment policy](REINVESTMENT_POLICY.md) makes bounded fee-balancing swaps part of the intended public MVP. Their owner-benefit model, quotes, token accounting, signing and on-chain path remain unimplemented; the practice cost check is balanced-assets only. This revision changes no live personal-bot limits or permissions.

Run the checks appropriate to each changed layer: the web's domain tests, TypeScript check and application-source lint; the full Python backend suite; and the isolated contract arithmetic unit/fuzz suite. The provided component catalog is unchanged and excluded from application lint. HTTP integration checks validate the preview API and, separately, the new local read API. The current capital/price/NFT revision passed 200 backend tests, native v4 comparisons and live capital/NFT/HTTP probes. The web and financial contract implementations are unchanged. Browser usability testing remains a separate milestone; no usability or accessibility certification is claimed.

The report is not an execution backtest or a forecast. With the sampled observations and a hypothetical $0.25 gas cost, only eight observations had an in-range position and at least ten minutes of measurement. The sample is small, overlapping and changes as the live log grows. Re-run the command in `backend/README.md` for a new snapshot.

The first invited functional alpha now includes opt-in Domino alongside Auto-compound on admitted Robinhood v4 markets. A read-only build is an internal integration milestone. ## Remaining before real multi-user operation

The [Revert fee review](REVERT_FEES_REVIEW.md) and [approved pricing boundaries](PRICING_POLICY.md) also add monetized owner-requested assisted swaps to alpha requirements, with a 0.65% ceiling and separate 2% earned-fee automation rules. Current Revert documentation describes dynamic swap fees, not a universal flat creation fee. Domino's exact assisted-swap tariff, quoted fee basis, on-chain collection and receipt integration remain unimplemented; the practice app and live personal bot retain their current behavior.

1. Broaden Robinhood inventory/catalogue and reconciled event-time history, scale position reconciliation beyond the initial bounded sets, qualify timestamp-aligned independent USD sources and complete live 24h metrics, then calibrate compatibility/suggestion filters. Extend the implemented NFT ownership reads with wallet-wide NFT inventory, watchlists, authenticated sessions and transfer indexing; validate the pair/composition journey with intended users.
2. Implement wallet authentication, pool discovery, durable onboarding, exact funding quotes, owner-signed swaps and creation/import, including advanced pool initialization plus first mint; test partial completion, cancellation, competing initialization and native-ETH handling.
3. Implement the generic vault/factory, both compound paths, Domino successor creation/funding and bounded fee-balancing swaps with actual token accounting, price integrity, replay protection and owner escape.
4. Extend the local Python read API with authenticated durable account routes, private-account migrations and tenant-isolation/concurrency/restore tests. The standalone public-catalogue migration is applied and tested; the private-account `schema.sql` is still unapplied and unqualified.
5. Isolate the remote signer, add durable broadcast/reconciliation and economic observation history, and test failures/reorgs.
6. Complete independent audit, remediation, limited mainnet alpha and the operational/legal gates in the approved plan.

No real approvals, positions, token issuance or public-user access are enabled by this milestone. The personal bot's files and configuration remain separate from this implementation.
